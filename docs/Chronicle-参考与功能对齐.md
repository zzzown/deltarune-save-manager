# 参考 Chronicle 的功能对齐方案

> 本文件基于 [Chronicle](https://github.com/ThermalEX/Chronicle)（Rust + Tauri 2 + Vue 3 的通用存档时间线备份工具，GPL v3）的功能集，逐项对照到「Deltarune 专用存档管理器」，回答：**借鉴什么、精简什么、不要什么**。只借鉴功能设计思想，不复制其代码。

---

## 一、定位一句话

**保持「Deltarune 专用」，把 Chronicle 的"时间线备份体验"搬过来。**

不做的方向：不搞成"另一个通用存档工具"（那会丢掉我们对 filech 格式、槽位×章节×面矩阵、B 面、dr.ini 的深度理解，也浪费你给的字段映射资料）。

## 三、重点借鉴的 8 项能力（Deltarune 化）

### 1. 自动备份引擎 —— 最值得抄的一项

Chronicle 的自动备份不是"改一个文件就存一份"，而是：

1. **绑定游戏 `.exe`**（我们绑 `DELTARUNE.exe`）；
2. 检测到进程**所有实例退出**后，等待一段**静默时间**（默认 5s，可调 1–300s）；
3. 期间文件变化做**写入稳定合并**（debounce），内容未变则跳过。

这对 Deltarune 尤其正确：存档在**游戏退出时最终落盘**，所以"退出后备份"比"纯文件监听"更可靠、也更省（不会在每次 SAVE 时刷一堆中间快照）。

### 2. 星标锁定节点

快照加 `locked` 标志：被锁定的快照**不占"保留最近 N 个"的配额**，也**不会被自动清理**。

Deltarune 场景：每个世界线"关键分支前""通关前"的节点锁定，永久保命。主方案 §4.1 的"手动永久保留"升级为这一机制。

### 3. 定期健康检查

默认每 7 天（可设 1–365）核对：

- 快照的 SHA-256 是否仍完好；
- 来源文件是否可访问；
- 当前存档 vs 最新快照是否**有未备份变化**（指纹不同 → 提醒"该快照了"）。

Deltarune 额外加一条：`filech5_*_b` 存在但 `dr.ini` 对应 `SideB=0` → 报"B 面状态不一致"。

### 4. 快照压缩 + 内容寻址去重

`filech1_*` 单个 41 KB，多次快照会滚雪球。借鉴 Chronicle 用 `.7z` 压缩，且**相同内容（同 SHA-256）只存一份**。

MVP 先用"目录 + 原样文件"跑通，V1 引入压缩（Rust 侧 `zip` crate 起步稳，`.7z` 用 `sevenz-rust` 可选）。

### 5. 软删除体系

- 快照删除 → 先进"快照回收区"，可恢复；
- 保留策略清理 → 同样先入回收区；
- 删除依赖**明确操作记录**，不把"文件丢失/扫描失败"误判为删除。

对应到我们：`delete_snapshot` 先移入 `_trash`，提供"清空回收区"二次确认。

### 6. 排除规则（默认策略）

Chronicle 支持 `*.tmp`、`cache/` 排除。Deltarune 存档目录里的文件要区分对待：

| 文件 | 处理 |
|---|---|
| `filech{N}_{slot}[_b]` | **纳入**（存档本体，核心） |
| `dr.ini`（相关段） | **纳入**（元数据，段级合并） |
| `config_{0..4}.ini` / `keyconfig_*.ini` | 默认**排除**（设置非进度），可勾选纳入 |
| `steam_autocloud.vdf` / `true_config.ini` | 排除（云/系统生成） |
| `vacationmemories.png` 等媒体 | 排除 |

### 7. 托盘常驻 + 自启 + 通知 + 全局快捷键

关闭主窗口 → 缩到托盘，**继续监听游戏退出并自动备份**；支持随系统启动、备份完成通知、可录制全局快捷键。这是把"自动备份"从"开着才有"变成"装了就有"的关键。

### 8. 多目录自动发现 + 来源标识

Chronicle 识别多个 Steam 库。我们对应：**自动发现 `%LOCALAPPDATA%` 下所有 `DELTARUNE*` 目录**（本机就有 `DELTARUNE`、`DELTARUNE_bak`、`DELTARUNE_pink` 三个），每个目录作为一个"来源"，快照时间线可按来源筛选、卡片标注来源名。

> 这正是你机器上三个平行目录的产品化——不用再手动复制文件夹，管理器把"多个世界副本"当成可切换的来源。

## 四、不借鉴 / 精简项（附理由）

| 项 | 理由 |
|---|---|
| 通用游戏识别（Ludusavi/Galgame） | 专用工具，反而要锁死 Deltarune 语义 |
| 注册表来源 | Deltarune 无注册表存档 |
| 多源云同步 | Steam Cloud 已覆盖主场景；自建云同步是重活，放 V3 且可选 |
| 主题市场 / 角色壁纸 | 版权风险 + 非核心；内建一套 Deltarune 主题即可 |
| 手动分类树 | "槽位×章节×面"已是天然分类，世界线标签自动生成更省事 |

## 七、与当前代码的关系

已实现（MVP 骨架）：扫描器（含 `_b` 解析）、dr.ini 元数据、快照/事务恢复、进程守卫、原子写入、指纹。

本轮参考 Chronicle 后**新增/调整**：
1. 快照元数据加 `locked`（星标锁定）字段；
2. `delete_snapshot` 改为软删除（移入回收区）；
3. 扫描扩展为"多目录发现"（返回所有 `DELTARUNE*` 来源）；
4. 快照排除规则（默认只备 `filech*` + dr.ini 段）；
5. 索引从 SQLite 简化为 JSON（快照库 `index.json`）。

详见主方案 v0.3。
