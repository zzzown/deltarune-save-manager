# DELTARUNE 外置存档管理器 · 技术方案 v0.2

> 目标：做一个**不注入游戏、不改游戏本体**的独立存档管理工具，解决"多世界线 / 多周目 / 试错分支"场景下存档容易搞乱、丢了找不回的问题。

**v0.2 变更**：确认 Ch5「B 面（Side B / 怪异路线）」存档规则；把 `dr.ini` 识别为槽位元数据索引；核心抽象从「槽位×章节」升级为「槽位×章节×面」。

## 1. 产品定位

### 1.1 真实痛点

1. **一个"存档槽"横跨多个章节**，分散在多个文件里。玩家心里的"第三个存档"对应 `filech1_2`…`filech5_2` 一整列，手动复制只拷一半就会进度错乱。
2. **想同时保留多条世界线**（和平线 / 冰封线 / 暴力线 / 拔剑线 / 怪异路线），但游戏只有 3 个槽。
3. **试错分支**：想在某个选择前存一份、走错能回退，但存档点有限。
4. 现有在线编辑器只"改数值"，不做**版本管理**；`dr存档.rar` 里那些 `冰封线+拔剑线+暴力线` 目录证明玩家一直在手工整目录备份。

### 1.2 设计红线（Non-invasive）

- **不注入 DLL、不 hook 进程、不读内存、不改 exe**——纯文件级操作。
- 游戏运行期间**默认只读**，禁止写入。
- 任何写操作前**强制自动快照**。

## 2. 存档机制（本机实测 + wiki 核实）

### 2.1 目录与文件矩阵

```
%LOCALAPPDATA%\DELTARUNE\
├── filech{N}_{0,1,2}        # 第 N 章 · 存档槽 1/2/3（正篇）
├── filech{N}_{3,4,5}        # Completion FILE（通关凭证，槽 1/2/3 对应 3/4/5）
├── filech{N}_9              # 自动存档 / Game Over 续关卡（会被游戏覆盖）
├── filech5_{0..9}_b         # ★ Ch5「B 面」（怪异路线）平行档，见 §2.3
├── config_{0..4}.ini        # 各章设置
├── keyconfig_{N}.ini        # 各章键位
├── steam_autocloud.vdf      # Steam 云同步标记
└── dr.ini                   # ★ 槽位×章节元数据索引（关键数据源）
```

本机存在 3 个平行目录：`DELTARUNE`、`DELTARUNE_bak`、`DELTARUNE_pink`——玩家手工备份的痕迹，正是本工具要产品化的行为。

### 2.2 filech 文件格式（关键事实）

经逐字节确认：

- **纯文本**，`CRLF` 行尾，**一行一个值**，绝大多数行形如 `值 + 尾空格`（如 `10014 ^M$`）。
- **无字段名、无分隔符、无校验和**，字段靠**行号**定位。
- 浮点会用**科学计数法**序列化（文件末出现 `4.23475e+06`）→ 写入必须**逐行字节保留，只替换白名单行**。

两种布局：

| 布局 | 章节 | 行数 | 特征 |
|---|---|---|---|
| `legacy` | Ch1 | 10,318 | 约 9,999 行为故事 flag |
| `modern` | Ch2–Ch5 | 3,055 | 全局态 + 4 角色块 + 物品 + flag 尾部 |

字段映射已有可靠来源（`资料/DELTARUNE存档修改数据.txt`，作者「梦_wing」），要点：

| 字段 | Ch1 | Ch2/3/4 | Ch5 新增 |
|---|---|---|---|
| 玩家名 / 容器名 | 1 / 2 | 1 / 2 | 同 |
| 队伍槽 1/2/3 | 8/9/10 | 8/9/10 | 同（4=Noelle） |
| 暗币 D$ | 11 | 11 | 同 |
| Kris HP/上限/攻/防/魔 | 71–75 | 79–83 | 同 |
| Susie 块 | 125 | 141 | 同 |
| Ralsei 块 | 179 | 203 | 同 |
| Noelle 块 | — | 265 | 同 |
| 游戏时间（帧，÷30=秒） | 10318 | 3055 | 3055 |
| 粉币 / 花币 | — | — | **1865 / 1964** |

> **Ch5 比 Ch4 多了「粉币(1865)」「花币(1964)」两个货币字段**，印证字段映射必须按章独立、配置驱动。

### 2.3 Ch5「B 面」（Side B / 怪异路线）—— 完整规则

B 面 = **第五章怪异路线（Weird Route）** 的产物，官方在结尾画面标注 "Side B"，暗示其延续至 Ch7（"Insert Chapter 7 Side B"）。

**命名规则**（wiki 核实 + 你补充）：

| 文件 | 含义 |
|---|---|
| `filech5_0_b / _1_b / _2_b` | B 面三个常规存档槽 |
| `filech5_3_b / _4_b / _5_b` | B 面 Completion FILE（章节选择界面**不显示星星**） |
| `filech5_9_b` | B 面自动存档（当前版本**不可加载**，与其它 completion 分离） |

**格式**：与 Ch5 正篇**完全一致**（3,055 行、modern 布局），实测 `filech5_3_b` 与 `filech5_3` 逐字节同构，差异仅在队伍/金钱/坐标等正常进度字段。

**B 面身份的判据**（双重）：
1. **文件名 `_b` 后缀**（游戏靠它识别 Side B）。
2. **`dr.ini` 中 `SideB` 键**：完成怪异路线后，对应槽位段的 `SideB` 会被写为 `"1.000000"`。

> 结论：B 面不是"另一种格式"，而是**同一格式下的一套平行档**，用 `_b` 后缀 + `SideB` 标志区分。管理器无需为其另写解析器，只需在扫描/备份/展示层把它当成"面 B"对待。

### 2.4 dr.ini —— 元数据索引（重要数据源）

`dr.ini` 不是普通设置文件，而是**每个「章节×槽位」的元数据索引**，格式为 INI。实测结构：

```ini
[G_5_0]                     ; 章节5 · 槽位1（slot0）
SideB="0.000000"            ; ★ B 面状态（1 = 已完成怪异路线）
Name="ZZZ"                  ; 玩家名
Level="1.000000"            ; LV
Love="1.000000"             ; （同 LV 语义）
Time="4234749.000000"       ; 游戏时间（帧，÷30=秒）
Date="46236.423038"         ; OLE 自动化日期
Room="50230.000000"         ; 当前房间编号
InitLang="0.000000"         ; 语言
UraBoss="2.000000"          ; 隐藏 Boss（裏）状态
Version="v0.0.253"          ; 游戏版本

[G_5_2]                     ; 空槽示例
Name="[EMPTY]"
...

[URA]                       ; 隐藏 Boss 总表，键 {ch}_{slot}，值 0–3
4_2="1.000000"
3_0="3.000000"
...

[F_ITEMS]                   ; 物品标记，键 {ch}_{slot}_{idx}
5_0_0="1.000000"
...
```

**要点**：

1. 段名 `[G_{ch}_{slot}]`，ch 范围 0–5，slot 0–5（0–2 存档槽、3–5 completion）；还有旧式 `[G0]`/`[G3]` 全局段、`[video_ch5]`、`[URA]`、`[F_ITEMS]`。
2. **`SideB` 键只在较新版本写入**，缺失即视为 `0`（本机全部为 `0`，未开 B 面）。
3. `Name="[EMPTY]"` 标记空槽——扫描空槽的可靠信号。
4. 键顺序在每个段内**不稳定**（不同段排列不同），解析必须按键名取值，不能靠顺序。

**对管理器的价值**：读 dr.ini 即可拿到每个槽位的 `Name / Level / Time / Room / SideB / UraBoss`，**不必解析 filech** 就能画出槽位卡片与 B 面状态。数值编辑阶段才需要 filech 内容。

## 3. 核心抽象：槽位 × 章节 × 面

```
            Ch1   Ch2   Ch3   Ch4   Ch5   (未来)Ch6/Ch7
Slot 1  A   ●     ●     ●     ●     ●        ?
Slot 1  B   —     —     —     —     ◐(B面)   ?(Ch7 Side B)
Slot 2  A   ●     ●     ●     ●     ●        ?
Slot 3  A   ...   ...   ...   ...   ...
```

- 一个 **Profile（存档档位）** = 某「槽位 × 面」列上所有存在章节文件的集合。
- **面（Face）**：`A` = 正篇，`B` = 怪异路线（Side B）。目前 B 面文件只在 Ch5（`filech5_*_b`），wiki 暗示 Ch7 会延续 Side B，故 `filech{7}_*_b` 未来可能出现——命名规则泛化为 `filech{N}_{slot}[_b]`。
- **快照 = 整档快照**：备份 `Slot 1 A 面` 时，把 `filech1_0 … filech5_0` + 相关 `_9` + 对应 `dr.ini` 片段一次性打包。恢复时整列回滚，杜绝"Ch3 回退了、Ch4 还是新的"。
- **世界线标签**：由 `Name` + Ch1 关键 flag + 各章 Completion 存在性 + `SideB`/`UraBoss` 自动生成，例如
  `ZZZ · 和平线 · Ch1–4 已通关 · Ch5 进行中` 或 `ZZZ · 怪异路线(B面) · Ch5 已通关`

### 3.1 一致性体检

- 玩家名跨章一致（防止不同人的档混在一起）
- 章节链是否断裂（有 Ch4 无 Ch3 且无对应 completion → 警告）
- LV / Time 随章节单调递增（倒挂说明被替换过）
- `filech5_*_b` 存在但 `dr.ini` 对应 `SideB=0` → 提示「B 面文件与元数据不一致」

## 7. 关键技术方案

### 7.1 文件名解析（含 B 面）

```
filech{N}_{slot}[_b]   →   { chapter: N, slot: slot, face: (有 _b ? B : A) }
```

- 正则 `^filech(\d+)_(\d+)(_b)?$`；不匹配的（如 `filech4_2_old`）归入"其他文件"，**只备份不解析**，绝不误删。
- slot 语义：`0–2` 存档槽、`3–5` completion、`9` 自动存档；`_b` 同规则。
- 未来 `filech6_*`/`filech7_*` 自动接入，未知章节降级为 opaque（只备份）。

### 7.2 dr.ini 解析（元数据源）

- 用 INI 解析器读入，按键名取值（键序不稳定，不能靠顺序）。
- 构建 `HashMap<(chapter, slot), SlotMeta>`，字段 `Name / Level / Love / Time / Date / Room / SideB / UraBoss / Version`。
- `Name=="[EMPTY]"` → 空槽；`SideB` 缺失 → 视为 `0`。
- 额外读 `[URA]`、`[F_ITEMS]` 供世界线标签与进阶展示。

### 7.3 无损 round-trip 写入（数值编辑阶段才启用）

```
读原文件 → 按 CRLF 切分为行数组（保留每行原始字节含尾空格）
         → 仅替换白名单字段所在行
         → 校验：行数 == expectedLines；未改动行逐字节相等
         → 序列化回字节
```

铁律：不 `trim()` 重写整行；浮点/科学计数法行不碰；写前计算未改动行哈希、写后比对，任何差异即中止。

### 7.4 原子写入 + 三重保险

```
1) 写前快照（自动） 2) 写 X.tmp → fsync → 回读校验 → rename 覆盖
3) 滚动保留 X.bak ×3
```

任一步异常 → 从 `.bak`/快照回滚，报告失败阶段。

### 7.5 快照与恢复

- 快照为不可变目录/zip，含 `meta.json`（槽位、章节、**面**、来源目录、行数、SHA-256、备注、工具版本）。
- 恢复采用**事务式**：目标现有相关文件先移入 `_trash/<ts>/`，再落新文件，全部成功才提交；失败全量回滚。
- 恢复后回读校验（行数 + 哈希 + 玩家名 + SideB 一致），失败自动回滚告警。
- 支持"恢复到另一个槽位"（复制世界线而不覆盖原槽）。

### 7.6 并发与冲突

| 冲突源 | 检测 | 策略 |
|---|---|---|
| 游戏正在写档 | 进程 `DELTARUNE.exe` / 文件句柄占用 | **禁用写入**，恢复操作阻断 |
| Steam Cloud 回滚 | 比对 `steam_autocloud.vdf` / remote 目录 mtime | 提示"切换前建议临时关云同步" |
| 外部改动 | `fs.watch` + mtime + 哈希 | 提示"存档被外部修改，是否建快照" |
| 写锁/权限 | 打开失败重试 3 次（指数退避） | 提示管理员权限或杀软占用 |

**不做**自动关云同步——保持外置、不越界。

### 7.7 完整性指纹（旁路，不写回游戏文件）

```
fingerprint = sha256(bytes) + lineCount + first16Lines + last3Lines
```

用于发现静默损坏、识别重复快照、判断"快照是否即当前档"。

## 8. 风险清单

| 风险 | 等级 | 缓解 |
|---|---|---|
| 行数错位导致存档报废 | 高 | 行数强校验 + 只替换白名单行 + 写前快照 + `.bak` 滚动 |
| 游戏运行中写档被覆盖 | 高 | 进程检测硬阻断写入 |
| B 面文件被当成普通文件漏备/误删 | 高 | 文件名解析显式识别 `_b`；未知后缀只备份不解析 |
| `SideB` 标志与 `_b` 文件不一致 | 中 | 体检提示；恢复时二者一起校验 |
| 字段映射猜错改坏数值 | 中 | 只开放已验证字段；默认只读 |
| 章节格式变更（Ch6/7） | 中 | 配置驱动 + opaque 降级 |
| 杀软报毒 | 中 | 不注入/不 UPX；开源可解释 |
| 存档含个人隐私（玩家名） | 低 | 本地存储；导出前可脱敏 |
